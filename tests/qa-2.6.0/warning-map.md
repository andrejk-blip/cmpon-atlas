# Independent warning audit — baseline 2.5.0

Source inspection, not a claim that release 2.6 has passed. Baseline commit: `0391d60f26157648e96ce51c77278e261fffdab1`.

The requested combat rule concerns advance tactical markers. Physical enemies, incoming projectiles, damaging ring boundaries, actual monster limbs, crosshairs and navigation indicators must remain visible. `assist === true` is the existing calm/training flag. A silent HUD is insufficient if the same upcoming strike is announced by captain speech, comic, colored geometry or mobile objective.

## Release checks planned

- Exact final entry script hashes, tested without test-only production modifications.
- Pause and save/load at all 14 initial mission fixtures, both modes; old 2.5 snapshots preserve resources/progress/layout.
- Input contracts supplied separately by root: RMB rocket on every supported mission, simultaneous LMB/RMB, release/blur/pause/visibility cleanup, no context-menu interference.
- Natural input-only simulations for full campaign and isolated harder fights. Stationary fire is a separate negative control; the best scripted pilot is not a measurement of human difficulty.
- Forward-sector accessibility and actual shot damage against jammer/pursuit enemies; no teleport-to-target, zeroing HP, unlimited ammunition or victory assignments.
- Native Canvas captures at desktop, portrait, landscape and FX-off; unchanged saves after rendering, finite matrices, bounded mesh/listener counts. Native Canvas is not a browser/GPU/Android result.
- Browser evidence, real-time stress, sound listening and touch hardware are tracked separately by the release owner. A VM test cannot establish their success.
