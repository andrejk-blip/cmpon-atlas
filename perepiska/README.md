# Переписка

Игра о полевой команде, жителях и обследованиях населения. Игрок выбирает сотрудницу и дом, наблюдает её путь по двору, проводит короткую беседу у двери и заполняет анкету. После встречи сотрудница возвращается в штаб с результатом.

Визуальное направление — «Живая линия»: рисованные взрослые персонажи, свободный контур и небольшие выразительные реакции. Основной экран — движущийся двор. Диалог и электронная анкета открываются на время встречи.

## Содержание первой версии

- Кампания сплошного обследования небольшого двора.
- Три сотрудницы и четыре адресных задания; один адрес включает два домохозяйства.
- Прямой выбор сотрудницы и маршрута через карту; несколько коллег могут идти одновременно.
- Движение по дорожкам, гуляющие жители, перемещение и масштабирование камеры.
- Пауза, скорость 1×/2×, учёт доступности жителей и времени назначенных встреч.
- Передача задания другой сотруднице с сохранением сведений и договорённостей.
- Уточняющие вопросы перед подтверждением анкеты.
- Раздельные состояния сохранения, передачи и проверки данных. Возвращение в штаб передаёт и проверяет результат именно этой сотрудницы по текущему заданию.
- Следующая кампания по фиксированной выборке после завершения первой.

Все люди, адреса и ответы в сценариях вымышлены. Приложение не предназначено для проведения настоящей переписи или сбора персональных данных.

## Работа с проектом

Проект использует браузерные ES-модули. Игровое ядро не зависит от DOM и от сервисов магазина приложений. Для запуска страницы нужен HTTP-сервер: открытие `index.html` через `file://` не является поддерживаемым способом запуска модулей.

Команды сборки и тестов определены в `package.json`. Для разработки используйте поддерживаемую версию Node.js.

```sh
npm test
npm run build
```

## Где менять игру

| Изменение | Место |
| --- | --- |
| Сотрудницы, кампании, задания, реплики и ожидаемые ответы | `src/campaign.js` |
| Правила, переходы состояний и проверка сохранений | `src/engine.js` |
| Граф дорожек, поиск пути, движение сотрудников и жителей | `src/world.js` |
| Отрисовка персонажей, входов и маршрута; камера и касания | `src/scene.js` |
| Локальное сохранение, настройки, экспорт и регистрация офлайн-режима | `src/platform.js` |
| Связь игрового ядра с миром, встречи, анкеты, итоги и настройки | `src/app.js` |
| Оформление и адаптация к ширине экрана | `style.css` |
| Проверка игровых правил | `tests/engine.test.js` |
| Проверка движения и маршрутов | `tests/world.test.js` |
| Проверка сохранения и конфликтов между вкладками | `tests/platform.test.js` |
| Иллюстрации | `assets/` |
| Устройство проекта и переносимость | `docs/ARCHITECTURE.md` |
| Очередность развития | `docs/ROADMAP.md` |
| Выполненные проверки и ограничения | `docs/QA.md` |

`npm run build` создаёт каталог `dist/` со статическими файлами и служебным файлом офлайн-кэша. Веб-версию следует публиковать целиком из `dist/`. Исходники и документация остаются отдельно от результата сборки.

GitHub-копия содержит готовые WebP и шрифт с лицензией. Большие исходные PNG и TTF из `assets/source/` сохраняются в основном проекте и исключены из этой копии и опубликованной сборки.

Прогресс сохраняется в локальном хранилище браузера. В настройках можно экспортировать JSON-файл и загрузить его на другом устройстве. Импорт проверяет структуру файла; некорректный файл не должен заменять текущую историю. Очистка данных браузера удаляет локальный прогресс; автоматической синхронизации между устройствами пока нет.

Если другая вкладка уже записала новое состояние, старая вкладка не заменяет его своим прогрессом. Игра предлагает загрузить последнее сохранение. Явный импорт или подтверждённый новый старт могут заменить текущую историю.

Сохранение содержит ход обследования, а не покадровые координаты персонажей. При загрузке незавершённые беседы и возврат с собранными результатами восстанавливаются через маршруты от штаба. На назначенный, но ещё не начатый визит можно снова отправить сотрудницу нажатием на дом.

## Границы версии

Это браузерная версия с двумя короткими главами. Нативные сборки для iOS, Android и Steam, покупки, серверная синхронизация и публикация в магазинах в неё не входят. Подготовка к этим платформам заключается в разделении правил, содержания, движения и представления; для каждого магазина потребуется отдельная интеграция и проверка на устройствах.

Существующие игры проекта развиваются отдельно. Этот исходный код не заменяет «Цитадель требований» и прежнюю «Перепись 2030».
